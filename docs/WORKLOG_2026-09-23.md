## Этап 4 — последовательное исполнение TranscriptionJob: реализация в исходниках (24.09.2026)

На основе Windows-проверенного `WhisperMd-stage3-windows-verified.zip` подключено реальное исполнение очереди WPF поверх уже проверенного backend protocol.

Добавлено:

- `IWhisperBackendClient` — абстракция одиночного backend-запуска; WPF/application-слой больше не зависит от конкретной реализации PowerShell-клиента;
- `Execution/TranscriptionJobRunner` — последовательное выполнение immutable `TranscriptionJob` в порядке `Order`;
- `TranscriptionRunUpdate` — application-level события очереди (`ItemStarted`, `BackendEvent`, `ItemCompleted`, `ItemFailed`);
- `TranscriptionItemRunResult` и `TranscriptionJobRunResult` — результаты исполнения, включая точный snapshot исходного `TranscriptionJob` и `BackendRunResult` для каждой успешной записи;
- ошибка одной записи фиксируется как failed item и не останавливает обработку следующих файлов;
- `AsyncRelayCommand` для безопасного запуска длительной операции из WPF;
- кнопка `Начать транскрибацию` подключена к реальному исполнению очереди;
- во время запуска редактирование состава задачи блокируется, чтобы UI не расходился с immutable snapshot;
- статусы `Recording` обновляются по protocol events: подготовка, транскрибация, проверка результата, готово/ошибка;
- сохраняется выбранный фактический backend (`Vulkan` / `CPU`), в том числе после fallback;
- карточка записи показывает минимальный per-file progress и текст ошибки;
- после завершения ViewModel хранит `LastRunResult`, который станет входом для этапа формирования Markdown-заметок.

`transcribe.ps1` и protocol v1 на этапе 4 не изменялись. Backend по-прежнему обрабатывает ровно одну запись; очередь находится отдельным application-слоем.

### Семантика отмены

Отмена означает отмену **всей текущей очереди**, а не только одного файла:

1. активный backend process tree останавливается;
2. активная запись становится `Отменено`;
3. следующие записи не запускаются и также получают `Отменено`;
4. уже успешно завершённые и уже упавшие записи сохраняют свои состояния;
5. после фактического завершения процесса очередь снова становится редактируемой и её можно запустить заново.

Отмена не должна удалять исходную запись. Так как `transcribe.ps1` принудительно завершается на уровне process tree, временный WAV/частичный result directory могут остаться для диагностики — это допустимо и безопаснее автоматического удаления.

## Этап 6 — сборка и сохранение Markdown-заметок: реализация в исходниках (24.09.2026)

Этап 6 реализован поверх ещё не прошедшего отдельную Windows-проверку stage5, чтобы этапы 5 и 6 проверить одним локальным циклом.

Добавлен слой `src/WhisperMd.App/Notes`:

- `MarkdownNoteService` — связывает построение и сохранение заметок;
- `MarkdownNoteDraft`, `SavedMarkdownNote`, `MarkdownNoteSaveResult` и failure-модель;
- `INoteConflictResolver` + WPF-реализация conflict dialog;
- безопасная нормализация Windows-имён файлов.

Реализованы все три режима:

- `Separate`: один успешный аудиофайл -> один Markdown рядом с исходной записью; имя заметки берётся из имени аудиофайла;
- `Combined`: все записи собираются в одну Markdown-заметку в порядке очереди; пользователь может задать название, при пустом поле используется имя первого файла + fallback;
- `CustomGroups`: каждая пользовательская группа становится отдельной заметкой; имя группы становится названием заметки; записи без группы собираются в отдельную заметку.

Для объединённых заметок каждый исходный фрагмент получает отдельный `##`-раздел `Часть N — <имя файла>` и разделитель между частями. Если отдельная запись очереди завершилась ошибкой, в aggregate-заметке сохраняется явный Markdown-placeholder вместо молчаливого пропуска. В `Separate` заметка для неуспешной записи не создаётся.

Правило output до stage8: отдельная заметка сохраняется рядом со своим исходным аудио; Combined/CustomGroups — рядом с первой записью соответствующей заметки. Stage8 позднее заменит это фиксированное правило на пользовательскую папку библиотеки.

### Конфликты файлов

Если `<title>.md` уже существует, WPF показывает диалог:

- `Да` — заменить;
- `Нет` — сохранить копию `(2)`, `(3)`, ...;
- `Отмена` — пропустить только эту заметку.

Запись Markdown выполняется через временный файл в той же папке и атомарный `File.Move(..., overwrite: true)`. Ошибка сохранения одной заметки не должна препятствовать попытке сохранить остальные; итог различает saved / failed / skipped.

- в режиме `Combined` появилось поле `Название заметки`;
